命令行

operad help 会打印命令表；本页说明每个命令做什么、接受哪些选项、打印什么。dev 插件的命令也在它自己的页面；终端客户端在它自己的页面，pair 在应用页面，mcp 在 MCP 页面，环境变量在环境页面。

为什么需要它#

operad 是在终端、脚本或 agent 里访问一个 home 的唯一入口：设置它、启动 serve、查看 pending、回答 pending，以及运行插件声明的命令。CLI 并不写死插件能做什么。插件声明自己的对象类型、action 和 verb，CLI 据此生成 operad <plugin>:<action> 及其选项，所以新插件无需改动 CLI 就能在命令行中使用。大多数命令直接读写 home，因此无论 serve 是否在运行都能工作；让 run 继续推进的是 serve 这个进程，CLI 自己不做这件事。

它如何工作#

  1. 命令先找到 home：$OPERAD_HOME，否则是 ~/.operad。它打开 store，并加载 config.json 中启用的插件。这一步不需要任何进程在运行。
  2. 它为这些词选择路由。内核命令（pending、list、show、history、settings、plugin、secret、trigger，以及命令表中的其余命令）由 CLI 处理。<plugin>:<action> <id> 对一个对象运行 action；<plugin> <verb> 运行该插件声明的 verb，只有一个插件声明它时可以只写 <verb>。见 Actions。
  3. 读取类命令打印插件产生的行和 section。输出是给终端看的文本，加 --json 则是 JSON；见过滤列表和 History section。
  4. 会改变状态的命令，例如 action 或对 pending 项的回答，会把记录写入 home。正在运行的 serve 读到记录后，继续 run 所请求的 step。没有 serve 时，回答会打印 recorded; it runs when operad serve is running。
  5. operad serve 在打开 store 或端口之前先取得 home 锁（serve.lock），所以同一个 home 的第二个 serve 会以退出码 4 退出，并且什么都不改。operad serve stop 向该锁中记录的进程发信号；见停止 serve。
  6. 每个命令都以某个退出码结束，脚本因此能区分出错（1）、用法错误（2）和状态不允许（3）。

退出码#

退出码含义
0命令完成了要求的事，或没有事可做。
1出错：id 有误、config 或插件无法加载、检查被拒绝、编辑器失败。
2用法错误：未知的命令或选项、缺少参数、值不合法。附近有相近的命令时，消息会指出最接近的那个；缺少参数时打印该命令的一行用法；最后以一行指向 operad --help 的提示结束。
3当前状态不允许该操作：插件已禁用、有 run 正在进行、任务所处的阶段不允许这项更改、serve 没有在限时内停止。
4另一个进程持有 home 锁，或同一个 home 已有第二个 serve。
141读取方关闭了管道（128 + SIGPIPE）。之后的输出会被丢弃。

命令#

CLI 自身拥有的命令，在下表注明处接受紧跟在命令名之后的 --help；插件的 verb 会原样收到它的参数。operad --help 和 operad help 会打印完整的命令表。

命令参数作用与输出
operad无home 不存在时创建它，没有 serve 响应时启动它，并在默认 bot 的主 chat 上打开终端客户端：有绑定 Telegram 的 chat 时是它，否则是它最近一个打开的 chat（定时 prompt 打开的 chat 不算）。没有打开的 chat 时，它打开一个新 chat，光标位于输入框中，第一条消息会创建它。新 chat 是 bot 上的 bot:chat。
operad doctor[--json]检查 home，不改动其中任何内容。每项检查打印一行，ok 或 problem：home 和 config.json、每个已启用的插件、每个 agent 及其版本和是否已登录、serve 是否有响应、没有安装 git 时说明这一点的一行 ok（chat 不需要 git；任务需要），设置了 dev.testHost 时的测试主机，以及 operad pending 报告为设置问题的内容。problem 行以接下来要输入的命令结尾；对未登录的 agent，当 operad 能登录该 agent 时是 operad bot:login <bot>，否则是该 agent 自己的命令。只要有一行是问题，就以 1 退出。--json 打印 { "ok", "checks": [{ "id", "ok", "message", "next" }] }。
operad init无在 config.json 缺失时创建它，并检查每个已加载的插件。打印 created <file> 或 using <file>，然后每项检查打印一行 <plugin>: <result>。新 home 启用 chat、bot 和 memory，并为在 PATH 上找到的命令启用 radian、claude 和 pi；shell、dev 和 pool 在被启用之前保持关闭。找到 claude 时，它还会在 home 中安装 @operad-io/harness-claude 及其 SDK。一个 agent 都找不到时，它启用 pi，并在 home 中安装 operad 自己固定版本的 pi；这次下载需要联网一次，再次运行 operad init 会重试。codex 在 operad plugin enable codex 之前保持关闭。已启用插件的检查是：shell 开启时即就绪，每个已启用的 harness 在 PATH 上找到它的 agent，对 pi 来说也可以是 operad 安装的那一份，dev 开启时连通每个已注册仓库的 remote（见 dev 命令）。检查失败时退出码为 1。
operad serve无运行此 home 的循环：启动等待、运行 step、提供 HTTP 服务并运行 notify。为每个监听地址打印 http <url>，最后打印 serving <home>。另一个 serve 持有该 home 时退出码为 4。
operad serve stop--timeout <secs>用 SIGTERM 停止此 home 的 serve；见停止 serve。
operad pending--json列出等待人处理的事项：run、step、对象的标题、提示、选项和 action。为空时打印 nothing is waiting。
operad list <type>--filter <name>、--repo <name>、--parent <id>、--root、--where <field=value>、--limit <n>、--cursor <c>、--json列出某一对象类型的行。见过滤列表和层级。为空时打印 no objects of type "<type>"，后面还有内容时打印 next: operad list … --cursor …，过滤器漏掉了一些行时打印 N hidden (--filter all to show)。
operad show [<id>]--section <id>、--page <label or number>、--cursor <c>、--full、--raw、--json、--repo <name>给出 id 时：打印该行、它的父对象、它的子对象、各 section 的名称和可用的 action，然后打印第一个 section（或 --section 指定的）。不给 id 时：打印最近变化的十个对象和 operad show <id>。
operad history <id>--json以 History 的形式打印一个 run 的 step，或某个对象的所有 run。若一个裸 id 属于多个对象类型，会因有歧义而被拒绝。
operad running--json列出进行中的 run：对象、step、step 耗时、标题、run 的存续时间和排队时间。为空时打印 nothing is running。
operad flows--json列出已加载的 flow（包括 <home>/flows 中的文件，显示为 home:<file>）、各自所属的插件（这些文件为 home），以及某个 flow 无法启动的原因。为空时打印 no flows loaded。
operad plugin list无列出已配置的插件及其版本，以及 enabled 或 disabled。
operad plugin add <package>无把一个 npm 插件安装到 home 的插件目录中，并关闭它的安装脚本。<package> 是合法的 npm 名称，带确切的 @version，或不带版本表示最新版。运行与 operad plugin check 相同的检查，然后以关闭状态把它加入 config.json。打印包、它的版本、插件声明的名称和版本，以及 operad plugin enable 那一行。npm 不允许的名称、不确切的版本、不是 operad 插件的包，以及已被某个已配置插件使用的声明名称，都会被拒绝。
operad plugin enable <name>无在下一条命令时启用一个插件；config 中没有的内置插件会被加入。它所需要的、处于关闭状态的内置插件也会一并启用（dev 需要 pool 和 shell）。先打印包安装在运行过程中打印的那些行，然后为它打开的每个插件打印一行 <name>: enabled，被需要的插件在前；已经开启的插件不打印。禁用是逐个插件的：plugin disable pool 不会关掉 dev。启用 claude 会安装它的包；PATH 上没有 pi 时，启用 pi 会安装 operad 自己固定版本的 pi。下载失败时会说明，再次运行该命令会重试。
operad plugin disable <name>无在下一条命令时禁用一个插件。当有 run 正在使用它的某个 step 时拒绝，退出码为 3。打印 <name>: disabled。
operad plugin check <path>无加载一个插件声明，但不启动 run。打印 <name>: ok 或问题所在；有问题时退出码为 1。
operad secret set <plugin> <name>无从终端读取值且不回显，或读取 stdin 的第一行，并存储它。打印 secret "<name>" set for plugin "<plugin>"；值从不会被打印。
operad secret list <plugin>无每行打印一个该插件的 secret 名称，从不打印值。打印 no secrets for plugin "<plugin>"。
operad secret delete <plugin> <name>无删除一个 secret。打印 secret "<name>" deleted for plugin "<plugin>"。
operad settings--repo <name>、--json列出所有设置：作用域、名称、值、默认值、editable 或 read-only、是否要求确认、它的标题和它的描述。
operad settings set <name> <value>--repo <name>、--yes更改一项设置。值能解析为 JSON 时按 JSON 处理，否则当作普通字符串。要求确认的设置需要 --yes。打印 <name> = <value>。对于保存 map 的设置，例如 bot.bots，名称可以再深入（bot.bots.<name> 或 bot.bots.<name>.<field>），只更改一个条目而保留其他条目；规则相同，null 会删除该条目。
operad http token rotate无立即替换 bearer token。打印 http token rotated。
operad pair--url <url>、--show-token以二维码形式显示应用所用的地址和 token；见配对。
operad tui--url <url>、--token <token>、--no-start、--theme <name>打开终端客户端，并在没有响应时启动 serve；见终端客户端。
operad mcp--claude-channel、--types <t,…>在 stdio 上为 lead agent 运行 MCP 服务器；见 MCP 页面。
operad trigger <source> <key>--type <type>、--object <id>、--summary <text>、--data <file>让一个事件经过各条规则。打印 started <run>、waiting <pending id>、recorded in <run>、observed <flow> on <object>、not started: <reason> 或 recorded <id>。
operad trigger rules无打印当前生效的规则，以及每条规则来自哪个文件。打印 no trigger rules。
operad routines list--json列出 triggers.json 中的定时任务（按 schedule 启动的 flow）：每一个的 id、flow、cron schedule、对象、mode、下一次运行，以及上一次运行的结果和 run id。运行命令的定时任务在 flow 的位置显示 command "<line>"；失败的命令（非零退出码或超时）显示为 last failed <run id>: the command exited 3，它的输出末尾在 operad history 中。为空时打印 no routines。--json 把这些条目以 JSON 打印，供客户端使用。
operad routines add--flow <flow>、--command <line>、--cwd <dir>、--schedule <expression>、--params <json>、--object <id>、--mode <mode>添加一条启动某个已加载 flow 的 cron 规则；对象默认为 flow:<flow>，mode 默认为 auto。未知的 flow 或错误的 cron 表达式会被拒绝并说明原因。空白的 --params "" 不添加任何参数。用 --command "<line>" 代替 --flow 时，按 schedule 运行一条命令行（--cwd 设置它的目录；默认是 operad home），使用 shell 插件的超时、输出和访问规则，并且不接受 --flow 或 --params；它与 --flow shell:command --params '{"command":"<line>"}' 是同一条规则。shell 关闭时会被拒绝，并指出 operad plugin enable shell。打印新的定时任务及其 id。
operad routines to-flow <id>--name <name>把一个运行命令的定时任务变成一个你可以编辑的 flow 文件：写入 <home>/flows/<name>.flow.ts（默认名称为 routine-<id>），这个 flow 在同一个目录中运行同一条命令，并带有注释，说明如何添加 step、等待人处理，或按退出码分支。之后该定时任务改为启动 home:<name>。文件已存在、该定时任务不运行命令，或名称不是有效的文件名时会拒绝。见 home 中的 flow。客户端通过 action cron:to-flow 做同样的事，它不指向任何对象，接受 routine（id）和可选的 name，发送到不带 id 的 POST /v1/act。
operad routines edit <id>--flow、--schedule、--params、--object、--mode更改一个定时任务，保留其他的。schedule 改动后重新开始。--params "" 清除该 flow 的参数。打印 edited <flow> (<id>)。
operad routines pause <id>无停止该定时任务的 tick；暂停状态写在 triggers.json 中，重启后仍然保留。打印 paused <flow>。
operad routines resume <id>无在下一个计划的分钟恢复被暂停的定时任务。打印 resumed <flow>。
operad routines remove <id>无删除该定时任务的规则。打印 removed <flow> (<id>)。
operad:start <id>无启动由某个事件创建的 pending 项。打印 started <run>。
operad:dismiss <id>无忽略由某个事件创建的 pending 项。打印 dismissed <id>。
operad <plugin>:<action> <id>action 的参数、--yes、--repo <name>对一个对象运行一个 action；见 Actions。
operad <plugin> <verb>verb 的参数运行插件声明的 verb。当恰好有一个插件声明了该 verb，且没有内核命令使用这个名字时，可以只写 <verb>。
operad dev repo add <path>--name <name>注册一个仓库；见 dev 命令。
operad dev repo list无列出已注册的仓库。
operad dev repo remove <name>无移除一个已注册的仓库。
operad dev plan add--slug、--title、--concurrency、--flow、--repo创建一个计划并打印它的 id。
operad dev task add--plan、--slug、--title、--after、--area、--flow、--repo、--chat创建一个任务并打印它的 id。
operad dev task edit <id>--repo用 stdin 或 $EDITOR 替换一个 proposed 或 ready 任务的 brief。打印任务 id。
operad dev task update <id>--title、--after、--area、--flow、--repo更改一个任务并打印它的 id。
operad dev start <task>--repo请求启动一个 ready 任务。打印 start requested for <id>。
operad dev reruns无列出仅在 rerun 时才通过的测试，以及它们所属的任务。
operad bot skill <bot> <name>--from <dir>提议一个新的或已更改的 skill；由人批准。
operad bot mcp <bot> <name> [<command> [args…]]自身没有选项；命令中的词是服务器的读取一个本地 MCP 服务器的 tools 后提议注册它。不给命令时，从 stdin 读取粘贴进来的 mcpServers 条目。
operad bot setting <bot>无根据 stdin 上的 JSON，为一个 bot 提议更改设置；由人批准。
operad bot setup-dev <bot> <repository directory>< dev.jsonSetup Dev：没有输入时，它打印给 agent 的步骤；stdin 上有该仓库的 dev.json 时，它提议为该仓库打开 dev，由人批准。
operad bot setup <bot> <plugin> [target]Setup <name>：打印该插件自己的检查发现缺少的内容，以及它的设置指南中的步骤，供 bot 的 agent 照着做。在 bot chat 中，/setup <plugin> [target] 会把同样的内容发到 chat 里。
operad bot setup-git <bot> <folder>< {"gitignore", "identity"}在这里设置 git，供 bot 的 agent 使用：没有输入时，它打印步骤（缺少 git 时安装它，每条命令都是一个经批准的 pending 项，然后是提议）；stdin 上有一个 JSON 对象时（{} 表示使用默认值），它为一个没有 git 或没有 commit 的文件夹提议第一个 commit：.gitignore、文件列表以及名字和邮箱（预先从电脑账户填好），由人在 Pending 中批准。位于另一个 git 仓库内的文件夹、home 文件夹和磁盘根目录会被拒绝。
operad bot schedule <bot> add|edit|remove <name>--words <text>、--schedule <cron>、--prompt <text>、--model <model>、--effort <effort>提议添加、更改或删除一个定时任务；由人批准。
operad bot follow-up <chat> --at <time> --do <sentence>--at <time>、--do <sentence>在 bot chat 中设置一个 Follow-up；立即生效。供该 chat 的 agent 使用；见 Follow-ups。
operad bot follow-ups <chat>--cancel <id>列出该 chat 的 follow-up，或用 --cancel 取消其中一个。
operad memory search <query>--scope <scope>、--field <name>=<value>、--limit <n>搜索共享的 wiki、bot 的 memory 和 bot 的 chat。打印每个结果的文档 id、标题、行范围和片段，然后是随结果一起返回的目录说明。--scope 接受 wiki、memory 或 chats；--field 按 frontmatter 缩小范围；--limit 限制结果数量。同样的参数也可以作为 JSON 从 stdin 给出。
operad memory read <id>from、to、--json读取搜索返回的一个文档，或由 from 和 to（都从 1 开始）指定的行范围。读取一篇被其他笔记链接的笔记时，末尾会附上它的 Backlinks，每一条带有链接它的笔记的路径、行号和一段摘录。默认打印文本；--json 给出同样的结果，包括一个 backlinks 数组。id 和范围也可以作为 JSON 从 stdin 给出。
operad memory score--cases <dir>、--bot <name>、--memory <dir>、--window <n>、--no-record、--answer-with <program>对 bot 当前的 memory 运行 memory 回归集，并把分数追加到 home 中的 memory-scores.jsonl。打印分数、与同一回归集上一次运行相比的变化，以及每个失败的用例。见回归集。
operad memory propose--chat <id>在 chat 记录中找出更正，把每一条存为一个 pending 项；带着正确答案应当说出的短语批准其中一项，就会添加一个用例。打印提议了多少条。

定时任务的 verb 也可以带上插件名，以 operad cron routines ... 的形式使用；简写的 operad routines ... 是同一个命令。

serve 的客户端可以通过 HTTP 的 GET /v1/plugins 和 POST /v1/plugins 做同样的事，包括用 "install" 形式安装；见 Plugins。

选项#

选项命令含义
--helpCLI 自身拥有的命令打印该命令的用法。插件的 verb 会原样收到它的参数，因此 --help 会被传给插件，并可能因未知选项而被拒绝；请用 operad help 查看命令表。operad --help 打印完整的命令表。
--version、-Voperad打印 operad <version>。
--timeout <secs>serve stop等待被停止的 serve 多久：从 1 起的整数，默认 30。0、缺少值或不是数字都属于用法错误。
--jsonpending、history、running、flows、list、show、settings、routines list、memory read打印 JSON 而不是文本行。settings set 不接受它。
--filter <name>list要使用的过滤器；all 显示每一行。没有过滤器的类型会拒绝它。
--repo <name>list、show、settings、settings set、action、插件命令把列表限制在一个仓库内，或指明一个裸 id 属于哪个仓库。
--where <field=value>list对该类型的行所带的某个字段做一次精确匹配；可以重复。
--limit <n>list、memory search一页包含多少行，或返回多少条搜索结果。
--cursor <c>list、show前一页的 next cursor。
--parent <id>list父对象为该对象的行。不能与 --root 一起使用。
--rootlist没有父对象的行。不能与 --parent 一起使用。
--section <id>show要打印的 section；history 始终是最后一个。
--page <label or number>show有分页的 section 的某一页。不能与 --cursor 一起使用。
--fullshow跳过 section 的大小上限。
--rawshow按原样打印 section 的 Markdown，不带颜色。
--yesaction、settings set对确认回答“是”，或回答 action 所要求的确认。
--type <type>trigger事件类型；省略时为 event。
--object <id>trigger该事件所涉及的对象。
--summary <text>trigger事件的一行摘要。
--data <file>trigger事件的数据，从文件中读取。
--claude-channelmcp打开单向的 Claude Code channel。
--types <t,…>mcp把 channel 限制在这些对象类型内，以逗号分隔。
--url <url>pair、tui要指明的地址。对 pair 而言，它必须是 http 或 https，且不带凭据、query 或 fragment。
--show-tokenpair把 url、token 和 link 作为普通文本行打印，不显示二维码，即使输出不是终端也是如此。

停止 serve#

operad serve stop [--timeout <secs>] 停止当前 OPERAD_HOME 的 serve。它读取 serve.lock：

  • 没有锁，或锁对应的进程已不存在时，它打印 no operad serve runs for <home> 并以 0 退出。它不向任何进程发信号，也不删除过期的锁；下一个 serve 会替换它。
  • 进程仍然存活时，它先确认该进程是一个 serve：向操作系统查询该进程的命令行（ps -p <pid> -o command=，在 macOS 和 Linux 上相同），并要求 serve 是其中的一个单词。仅有锁是不够的，因为一个 serve 死亡后，它的 PID 可能被复用。当该进程不是 serve 时，命令会打印一条点明该 PID 的错误，不向任何进程发信号，并以 3 退出。
  • 否则它发送 SIGTERM（serve 本来就会处理的停止信号），打印 stopping operad serve (pid <pid>)，等到进程消失或锁被释放，打印 stopped 并以 0 退出。它从不发送 SIGKILL。

--timeout <secs> 是它等待的时长：整数秒，至少为 1，默认 30。若在此之后 serve 仍在运行，它会打印一条说明其未能停止的错误，并给出 kill -9 <pid> 作为强制停止的办法，然后以 3 退出。--timeout 为 0、没有值或不是整数，都属于用法错误（退出码 2）。不带子命令的 operad serve 照旧运行循环。

正在运行的工作会怎样：SIGTERM 让循环在当前这一轮结束后退出，随后 serve 停止 notifier、HTTP 服务器和 trigger 源，释放锁并退出。它不会杀掉 step。当 serve 停止时，在自己进程中运行的 step 会继续运行，该 home 的下一个 serve 会重新接管这个 run。没有 serve 运行时，没有任何东西会启动新工作，也不会推进等待和计时器；operad serve 或 operad tui 会让它们恢复。

step 会自行清理：它结束时，它启动的、仍在运行的每个进程（例如 worker 留在后台的循环）都会被停止，step 的日志会列出它们。启动时，serve 对不再活跃的 run 的 step 做同样的清理。关于如何找到这些进程以及哪些找不到，见 packages/dev/REFERENCE.md 中的 "What a step cleans up"。

重启不会打扰正在运行的检查或命令。每个 run 都是独立的进程，step 启动的命令由该 run 持有，而不是由 serve 持有：停止和启动 serve 不会向它发信号，不会停止它的那一行，也不会把它再运行一次。该命令自行结束，run 照常记录它的退出码，就像什么都没发生一样。只有 run 自己的进程死亡才会停止它的命令（此时下一个 serve 会重新开始这个 step）。

代码变更#

serve 和每个 run 的进程只在文件变化之前一直运行它们加载的代码。serve 监视内核的代码（engine、cli）、home 的 flow 文件、每个已加载插件的包（源码、flow、schema）以及该包所依赖的 workspace 包。文件安静一秒之后，它会启动一个新进程来检查新代码能否加载。若能，serve 以 operad serve stop 的方式停止，打印 reloading: <what changed>，并使用同样的命令行和环境重新启动，仍处于你所启动的进程之下（它留在你的终端里，会转发 Ctrl-C，并以 serve 的退出码结束）。正在运行的 step 继续使用它启动时的代码并运行完毕；run 的进程会在 step 之间查看这些文件，若有变化，它就停止，以便由新进程执行下一个 step。operad history 为此显示一行 continuing on updated code。

无法加载的新代码（语法错误、无效的 schema）不会让任何东西停摆。serve 继续运行旧代码，并在它的错误输出上打印 code changed (...) but does not load; the old code keeps running: <problems>；当文件再次能够加载时，它会重新加载，如果是某个设置文件（config.json、triggers.json、keys.json）读取失败后被修好，同样如此。run 的进程不会在无法加载的代码上执行下一个 step：它把同样的一行打印到该 run 的日志（<store>/logs/runs/<run id>.out）中，并等待文件能够加载。设置文件在下次使用时重新读取；仅仅更改它们不会重启 serve。

检查不会无休止地运行。如果它没有按时完成（加载代码的新进程 60 秒，整个检查 90 秒），serve 保留旧代码，打印 code changed (...) but the check did not finish; the old code keeps running: <why>，并显示下面那一项。被搁置的变更会在文件变化时再次尝试，没有变化时每五分钟尝试一次，所以失败过一次的检查不会让 serve 永远停留在旧代码上。

当 serve 运行的代码比磁盘上的文件旧时，operad pending 会显示一项：serve runs older code than the files on disk: restart serve to load them (operad serve stop, then operad serve)。它出现在新代码无法加载时（见上文），或重启时无法监听它的地址、旧代码重新提供服务时。它没有 action，并在 serve 再次运行磁盘上的代码时消失：即文件加载成功且 serve 重新加载之后，或你重启它之后，或文件恢复为 serve 所加载的内容时。

当重启无法监听、旧代码重新提供服务时，该 serve 不会再次尝试同一个变更。它仍然沿用之前所运行内容的，是 operad 本身、按包名给出的插件（以及路径插件所 import 的文件），因此对这些的更改会让上面那一项持续显示。按路径给出的插件，以及自 serve 首次启动之后才启用的插件，会从磁盘上的文件重新加载，因此仅对这些的更改不会显示任何东西。下一个不同的变更会经过加载检查，并照常重新加载。

History section#

每个对象都有一个 History section（operad show <id> --section history，即网页和终端界面中的最后一个标签页）。它先按 run 分组，再按每个 step 的 attempt 分组。run 的标题写明 flow 和启动时间；run id 在该 run 的块末尾以小字出现一次，供支持人员使用。一个 step attempt 占一行：提供服务的主机的本地时间、step、attempt（大于 1 时）、启动的原因（当它不是顺理成章的下一个 step 时，如 after fail、after reverify）、结果、耗时（正在运行的 step 显示 running 和目前已用时间），以及被截成一行并以 … 结尾的结果详情。人的回答和事件各占一行。每新的一天以一行日期开头。

## dev run · started 21:38
**2026-11-08**
- 21:38:41  worktree  ready  1s
- 21:38:44  work  done  41m
- 22:20:01  review  fail  58s  packages/dev/src/gate.ts:1059 major …
- 22:21:01  work  attempt 2  after fail  done  1m
- 22:22:02  confirm  reverify  8m
- 22:30:02  you chose merge: via plugin, as dev
- 22:30:04  verify  after reverify  running  2m

operad show <id> --section history --full 会保留每条详情的完整内容。operad history <id> 以 UTC 时间打印每个 step；--json 为每个 step 打印一个对象，当 id 指向多个 run 时，则为每个 run 打印一个对象。

层级#

插件可以把它的对象排成多个层级。一行可以带有 parent：上一层对象的 id，可以是完整 id（plan:repo/P-0001），也可以是按 operad show 的方式解析的裸 id。内核原样传递它，从不自行编造。没有 parent 的行位于顶层。

  • operad list <type> --root 列出该类型中没有父对象的行；operad list <type> --parent <id> 列出父对象为该对象的行。普通的 operad list <type> 保持平铺。
  • GET /v1/objects?root 和 GET /v1/objects?parent=<id> 的作用相同。对它们而言 type 是可选的。不带 type 时，它们按稳定的顺序跨所有插件的类型列出：类型按 GET /v1/types 给出的顺序（插件加载顺序，然后是每个插件声明其类型的顺序），同一类型内的行按该类型的普通列表的顺序（按 id）。next 在整个顺序中翻页。root 和 parent 不能一起使用。
  • 该类型的过滤器在层级内生效：带 type 的请求使用指定的过滤器或该类型的默认过滤器；不带 type 时，每个类型使用各自的默认过滤器（或在该类型有指定过滤器时使用它）。hidden 统计该层级中被过滤器漏掉的行数。
  • 指向不存在对象的 parent 不算错误：列表为空。若某行的 parent 指向一个不存在的对象，它仍会列在 parent=<that id> 之下，而不会列在 root 之下。
  • 当一行有父对象时，operad show <id> 会在该行下面打印 parent: <id>。
  • MCP 的 list tool 也接受 root 和 parent；见 MCP 页面。

过滤列表#

插件可以为对象类型提供过滤器，这样列表就不会显示每一个旧对象。在插件中，对象类型有一个可选的 filters 字段，是由 { "name": string, "states": string[], "default"?: boolean } 组成的有序列表：

objects: [
  {
    name: "task",
    filters: [
      { name: "active", states: ["proposed", "ready", "running"], default: true },
      { name: "done", states: ["merged"] },
    ],
  },
],

过滤器是数据：当一行的 state 是 states 之一时，该行匹配。state 为 error 的行（它的视图失败了）会被每个过滤器显示，因此有问题的行永远不会被隐藏。至多一个过滤器带有 default: true；一个都没标时，第一个是默认的。加载插件时，会拒绝空名称或重复的名称、两个默认过滤器、空的 states，以及名称 all，并指出出问题的字段。

内核会在默认过滤器之后紧接着加入过滤器 all，它不测试任何 state。上面的任务列为 active、all、done。

operad list <type> [--filter <name>] [--repo <name>] 在类型有默认过滤器且没有给出 --filter 时，使用该默认过滤器。--filter all 列出所有内容。当过滤器漏掉了一些行时，最后一行是 N hidden (--filter all to show)。--repo 只保留一个仓库的对象，并可与 --filter 一起使用。没有过滤器的类型会以 "this type has no filters" 拒绝 --filter。HTTP 接口以 filter 接受同样的选择（见下面的端点）。

dev 插件声明了这些过滤器（all 跟在 active 之后）：

类型过滤器State
taskactive（默认）proposed, ready, running, review, integrating, waiting, paused
taskdonemerged
taskcancelledcancelled
planactive（默认）draft, confirmed, paused
plandonefinished
plancancelledcancelled
repoactive（默认）active
reporemovedremoved

chat 插件声明了 open（默认）和 closed；all 跟在 open 之后。bot 插件声明了 open（默认）和 removed；all 跟在 open 之后。bot 的 proposal 类型声明了 pending（默认）、applied 和 rejected。

Actions#

action 以 <plugin>:<action> <id> 运行，或以 <plugin> <action> <id> 运行，或在只有一个插件提供该 action 时以 <action> <id> 运行。命令行为 action 声明的每个参数生成一个 flag：

operad dev:reject T-0003 --note "cover concurrent writers"
operad dev confirm T-0003 --yes
operad chat:send C-0001 --note "why does the gate fail on main?"
operad chat:model C-0001 --model sonnet

必填的 note 没有 --note 时，在终端中会被询问，在管道中则被拒绝；confirm: true 的 action 会询问 [y/N]，--yes 跳过这个询问。action 返回值时，会打印它的记录。打开对象的 action（opens）只打印它那一行；由终端和应用来打开该对象。记录一个回答的 action，会打印 recorded; it runs when operad serve is running，前提是没有 serve 持有该 home。

dev 命令#

operad dev repo add <path> [--name <name>] 注册一个目录。该目录不需要 git，机器也不需要 git 程序：这样的文件夹按原样添加，.operad/dev.json 设为就地工作且不指定 remote，只有在创建任务时才需要 git。没有 remote 的仓库也可以，它的 merge 留在本地的 main 分支中。对于位于某个 git 仓库内的目录（"<dir>" is inside the git repository at "<root>"; add "<root>" instead）、名称已经注册且未被移除，或路径已经以另一个仍在使用的名称注册的目录，它会拒绝，不写入任何内容，并打印原因。仓库没有 .operad/dev.json 时，它会写入一个。仓库已被移除的名称可以在新路径上重新注册，并保留它的计划和任务：要移动仓库的文件夹，先移除该仓库，移动文件夹，再用同一个名称重新添加。operad init 会对每个已有 commit 的已注册仓库检查其 remote 能否连通、主分支是否已发布（没有 git 的文件夹会被跳过）；它只以只读方式询问 remote，不会推送任何内容。operad dev repo list 打印 no repositories，或每个仓库一行 <name> <path>。operad dev repo remove <name> 打印 removed <name>。如果仓库有未完成的任务，它会拒绝（repository "<name>" has <n> open task(s)）；请先 merge 或取消这些任务。

operad dev plan add --slug <slug> --title <title> [--concurrency <n>] [--flow <name>] [--repo <name>] 创建一个计划并打印它的 id。 有 stdin 时，请求从 stdin 读取。--concurrency 是从 1 到 16 的整数，省略时默认为 1。

operad dev task add --plan <plan> --slug <slug> --title <title> [--after <task>]… [--area <area>] [--flow <name>] [--repo <name>] [--chat <id>] 在指定的计划中创建一个任务并打印它的 id。 有 stdin 时，brief 从 stdin 读取。--after 可以重复；该任务会等到每个指定的任务都被 merge 之后。另一个仓库的任务写作 <repository>/<task id>。任务不能跟随它自己，也不能构成环。--chat 使用该 chat 所请求的 worktree。

operad dev task edit <id> [--repo <name>] 替换一个 proposed 或 ready 任务的 brief。当 stdin 不是终端且带有内容时，新的 brief 就是 stdin 上的文本，否则是你在 $EDITOR 中保存的内容（EDITOR 未设置时用 $VISUAL）。没有编辑器也没有输入时，命令失败并说明这一点。它打印任务 id。

operad dev task update <id> [--title <title>] [--after <task>]… [--area <area>] [--flow <name>] [--repo <name>] 更改一个任务并打印它的 id。 --after "" 清除它所等待的任务；--area "" 清除 area。flow 只能在第一次 attempt 之前更改；之后命令会拒绝。

operad dev start <task> [--repo <name>] 请求启动一个 ready 任务，并打印 start requested for <id>；下一轮 serve 会认领它。

operad dev reruns 为每个仅在 rerun 时才通过的测试打印一行：<count> <test name> <task id>；没有这样的测试时，打印 no test has passed on a rerun yet。

简写形式 operad repo …、operad plan …、operad task …、operad start … 和 operad reruns 之所以可用，是因为只有 dev 声明了这些 verb。

bot 命令#

operad bot skill <bot> <name> [--from <dir>] 提议一个新的或已更改的 skill。不带 --from 时，stdin 是一个带有 skill_md 和 files 的 JSON 对象；带该选项时，读取该目录中的文件。skill 需要一个 SKILL.md。在有人于 pending 中批准该提议之前，不会写入任何内容。

operad bot mcp <bot> <name> <command> [args…] 启动一次本地 MCP 服务器，读取它的 tool 列表，并提议注册它。不给命令时，stdin 是粘贴进来的 mcpServers 条目。包命令（npx、bunx、uvx、pipx）必须指明确切的版本，如 name@1.2.3；tag 或版本范围会在服务器启动之前被拒绝。远程服务器（给出地址的）目前还无法注册。

operad bot setting <bot> 从 stdin 读取一个 JSON 对象并提议该更改。bot 可以收紧默认的访问配置，但绝不能放宽。MCP 服务器不在这里更改；请使用 bot mcp。

operad bot schedule <bot> add|edit|remove <name> 提议添加、更改或删除一个定时任务。add 接受 --schedule、--words 和 --prompt；edit 接受要更改的一个或多个字段以及 --words；remove 接受 --words。可选的 --model 和 --effort 设置或清除这两个字段。提议会以文字和 cron 两种形式显示 schedule，并显示 prompt、model 和 effort；在人批准之前不会运行任何东西。
