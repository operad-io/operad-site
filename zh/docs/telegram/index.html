Telegram

telegram 插件让你从 Telegram 给 bot 写消息，并在那里回答等待人处理的事项。你发的消息会在某个 bot 上打开一个 chat；bot 的回复回到 Telegram；agent 提出的问题会作为一条消息送达，每个选项对应一个按钮。它是可选的，只在 operad serve 运行时工作。

为什么需要它#

手机 app 和终端不一定随手可用，而 Telegram 总是在手边。这个插件把同样的 chat 和同样的 pending 项放进你本来就开着的对话里。没有任何东西是副本：chat 就是 app 里显示的那个 chat，在 Telegram 里回答的事项，在所有地方都算已回答。

设置#

  1. 在 Telegram 里与 BotFather 对话，为 operad 创建一个新的 bot。不要复用其他程序已经在用的 bot：Telegram 只允许一个客户端为某个 token 拉取更新，所以两个程序共用一个 token 会互相抢走消息，其中一个会停止工作。
  2. 查到你自己的数字 Telegram user id。报告它的 bot（例如 userinfobot）由第三方运行，对方能看到你发给它的内容；这个 id 也在你自己的 bot 通过 Bot API 收到的任何更新的 from 字段里。
  3. 启用插件，并把 token 存为插件的密钥：

``sh operad plugin enable telegram operad secret set telegram token ``

token 不会进入 history、日志行或错误信息。

  1. 把你的 user id 写进 config.json（见设置），然后启动 operad serve。
  2. 在私聊中给 bot 发一条消息。chat 会在 telegram.bot 指定的 bot（默认是 default）上打开，回复会到达同一个 Telegram 对话。
{
  "plugins": {
    "telegram": {
      "settings": {
        "users": [123456789],
        "bot": "default",
        "pending": ["dev"]
      }
    }
  }
}

已列出的用户能做什么#

id 在 telegram.users 中的用户，在与 bot 的私聊中：

  • 向 chat 写消息。第一条消息在 telegram.bot 指定的 bot 上打开一个 chat，并把它绑定到该 Telegram 对话；之后的消息进入同一个 chat。每个已列出的用户都有自己的 chat。chat 关闭后，下一条消息会打开新的 chat。这条消息是你的：它算作由你写出，发送者是你的 Telegram user id，run 的 history 会注明是哪条 Telegram 消息启动了它。
  • 点按钮回答问题。一次点按算作你的回答，以你的 Telegram user id 给出；当 action 要求确认时，它也算作确认。
  • 通过回复消息来回答需要文字的事项，例如 reject 或没有选项的问题。如果有多个这样的 action，回复以 action 的名称加冒号开头，例如 reject:。不是对这类事项的回复的文字，是发给 chat 的普通消息。
  • 回答 telegram.pending 中列出的插件的事项。设为 ["dev"] 时，dev 插件的 merge 和 confirm 事项可以从 Telegram 回答。
  • 输入 /pending 查看现在有哪些事项在等人处理，来自每个插件，不管 telegram.pending 列了什么。每个事项以会发送什么中描述的那种消息送达，已经在该对话中打开着的事项不会再发一次。
  • 输入命令，例如 /model sonnet、/effort high、/close 或 /help。它立即运行，在 chat 的 transcript 中留下一条记录，永远不会到达 agent。接受一个选项的命令在不带选项发送时，会用按钮来回应。

其他人什么都做不了。未列出的用户发来的消息，以及群组中的每一条消息，都会被记录，但不作任何回应：不会打开 chat，也不会启动任何东西。未列出的用户的点按不算数。

命令#

Telegram 在消息输入框下方显示 chat 的命令：要输入的名称，以及 action 声明的那一行描述。这个列表跟随 chat；chat 关闭后没有可用的命令，新的 chat 会把列表带回来。名称不被 Telegram 菜单接受的命令（菜单只接受小写字母、数字和下划线，最多 32 个字符）不会出现在菜单里，但输入它时仍然会运行。

命令像其他文字一样输入，/model@your_bot sonnet 与 /model sonnet 相同。Telegram 自己的 /start 会回一句简短的问候，指向 /help；它永远不会到达 agent。在你还没有 chat 时输入的命令会打开一个 chat，和第一条消息一样。

接受一个选项的命令，例如 /model 或 /effort，不带选项发送时不会运行，而是为每个选项回一个按钮。选项多到放不下时，« 和 » 打开其他页。点按其中一个会带着该选项运行命令，按钮消失，消息以 chosen: <choice> 结尾。输入的命令返回的内容会作为一条消息发回，所以 /help 列出命令，/close yes 会说 chat 已关闭。只有已列出的用户的命令会运行；其他人发来的命令会被丢弃，不作回复。

会发送什么#

  • 绑定到 Telegram 的 chat 的每条回复，以及说明回复失败的那一行。Markdown 会被精简为 Telegram 能显示的内容（粗体、斜体、代码、链接；标题和列表变为普通行），较长的回复会分成多条消息发出。发送失败会以逐渐变长的等待重试。插件第一次运行之前写出的回复不会发送。
  • 正在输入的提示。绑定到 Telegram 的 chat 的回复正在写的时候，那个 Telegram 对话会显示 bot 正在输入；回复或失败行被记录下来，或者回复结束、失败或被取消时，它就停止。
  • 命令返回的内容，以及 /start 回的问候。
  • 回复的进度，以一条不断被编辑的消息呈现。agent 写出第一段文本或开始一次工具调用之后，这条消息显示它目前已写的内容和仍在运行的工具调用。它最多每两秒变化一次，并且只在文本有变化时才变；文本很长时显示它的末尾。回复完成后，回复作为新消息到达（这样手机只通知你一次），进度消息被删除。失败或被停止的回复会移除它，或把它替换为失败行。在有内容可显示之前什么都不显示，进度编辑失败也绝不会妨碍回复送达。
  • 绑定到 Telegram 的 chat 中每个等待的事项，以及 telegram.pending 中列出的插件的每个事项（发给每个已列出的用户）。它是一条消息，每个选项一个按钮。从任何地方（Telegram、app、命令行）回答之后，按钮消失，消息以 answered: X 结尾，X 是所选的选项。点按一个已被回答的事项会提示这一点，不做任何改动。
  • /pending 发送的内容：先是简短的一行，说明有多少事项在等，然后每个等待的事项以上面那种消息发出。已经发过且仍然开着的事项不会再发一次，计数行会说明有多少个已经发过；没有事项在等时，这一行会说明这一点。

重启#

插件把它已读取和已发送的内容保存在 <home>/telegram/ 下。serve 停止后再启动，不会有消息被写两次，不会有回复被发两次，也不会有遗漏。已停止的进程留下的进度消息会在下一次启动时删除。

无法工作时#

  • the telegram plugin has no token：运行 operad secret set telegram token。
  • bot 不回应任何人：该 id 不在 telegram.users 中，或消息是在群组里发的。
  • 来自 bot 的消息不再到达，而另一个程序使用同一个 token：为 operad 单独做一个 bot。
