config.json

config.json 配置 operad。本页说明 home 在哪里、该文件的每个键，以及每个插件的设置部分。http 的键也在 HTTP 页中，notify 的键在 notifications 中，mcp 的键在 MCP 页中，dev 的仓库设置在 dev 页中。

为什么需要它#

operad 需要一个地方保存一个人的配置：安装了哪些插件、store 在哪里、开启了哪些接口。这个地方就是 home 目录及其 config.json。home 没有该文件时由 operad init 写入，之后可以手工修改，或用 operad plugin enable 和 operad plugin disable 修改。operad 不会重写已经有 config.json 的 home，对于 operad init 写入的文件，也没有任何隐藏的默认值。

它如何工作#

  1. 命令先找到 home：设置了 $OPERAD_HOME 且不为空白时用它，否则用 ~/.operad。它在那里读取 config.json；没有该文件就没有插件。
  2. kernel 只读取它指名的键：plugins、store、http、notify、mcp 和 ask。其中某一项的值有误，会以一行消息拒绝该文件；未知的键被忽略。
  3. 对 plugins 中每个未用 "enabled": false 禁用的条目，kernel 导入它的 module（未给出 module 时用键名），并用该插件自己的 schema 检查该条目的 settings。
  4. 导入失败、设置无效或声明了另一个名字的插件不会加载。其余的仍会加载，serve 和 operad plugin check 会打印说明原因的那一行。
  5. 被禁用的插件不会被导入；它已存储的对象保留。
  6. 一次性命令在下次运行时重新读取该文件。运行中的 serve 监视该文件，在新文件加载成功时 reload；加载失败时，旧配置继续运行，问题被记入日志。已经开始的 step 沿用它开始时的设置。

各个键见各个部分，每个插件的设置见插件设置。

home#

operad 把它的状态保存在一个目录中：设置了 $OPERAD_HOME 时用它，否则用 ~/.operad。home 中有 config.json、store、secrets 目录、access-user.json、keys.json、triggers.json、tui.json 和 themes 目录。secret 文件的权限是 0600，位于权限为 0700 的目录内；本手册中没有任何地方会打印 secret。

}

当 home 中没有 config.json 时，operad init 会写入一个：安装了 shell、radian、chat 和 dev，store 位于 store/log.sqlite，http 在 127.0.0.1:7480 上开启，通知关闭，写入上面的 mcp.actions 和 mcp.confirmActions 列表，以及 600 秒的 ask grace。这些全部写入文件；其中没有任何隐藏的默认值。完全没有 config.json 的 home 没有插件，也不允许任何 lead action。

已有的 home 不会被重写。在已有 config.json 的 home 上运行 operad init 会保持该文件不变；唯一的例外是没有 plugins 键的文件，它会被加上默认插件，其他什么都不改。没有 mcp.actions 的 config.json 不允许任何 lead action。在这次变更之前创建的 home 已经列出了它的插件，但可能没有 mcp.actions；要保留 lead 的 action，请把下面几行加入它的 mcp 部分，然后重启 operad mcp：

"mcp": {
  "actions": ["dev:rework", "dev:reverify", "dev:reject", "dev:priority", "dev:concurrency", "chat:close"],
  "confirmActions": ["chat:close"]
}

之后启用某个插件不会把它的 action 加入 mcp.actions；请手动添加。

每个顶层部分都是可选的。内核只读取它点名的键：顶层、引擎部分（store、http、notify、mcp、ask）内部，或 plugins 条目内部的未知键都会被忽略。唯一会拒绝拼写错误的地方是 plugins.<name>.settings，它由该插件自己的 schema 检查；那里的未知键会使该插件被拒绝，并给出一行指明插件和字段的信息。

插件设置#

插件设置位于 plugins.<name>.settings 之下。没有设置 schema 的插件没有键：shell 和 cron 来源（cron，即 @operad-io/source-cron 包）完全由它们的 flow step 和 triggers.json 配置。review-grading 是一个读取 <repository>/.operad/review.json 的库，记录在 dev 页中。MCP server、终端客户端、HTTP 接口和通知由上面的部分配置，而不是由插件设置配置。

每项设置都在插件加载时读取。运行中的 serve 在 config.json 变更且新文件加载成功时重新加载；已经启动的 step 保留它启动时的设置。例外情况在各表中说明。

triggers.json#

home 中的 triggers.json 保存规则，规定哪个事件启动哪个 flow。它是一个 JSON 数组；文件缺失表示没有你自己的规则。你的规则会替换具有相同 source 和 type 的插件规则；该组合的插件规则随后不再使用。

[
  {
    "source": "operad",
    "type": "dev.waiting",
    "start": { "flow": "dev", "params": {} },
    "object": "$event.object",
    "mode": "observe"
  },
  {
    "source": "cron",
    "type": "tick",
    "start": { "flow": "nightly" },
    "object": "flow:nightly",
    "mode": "auto",
    "schedule": "0 3 * * *"
  }
]
KeyTypeDefaultAllowed valuesWhen it takes effectWrong value
sourcestring必填发送事件的来源，例如 cron 或 operad读取文件时被拒绝：rule <n>: source: must be a non-empty string
typestring必填事件类型，例如 tick 或 run.done读取文件时被拒绝：rule <n>: type: must be a non-empty string
startobject必填下面的键读取文件时被拒绝：rule <n>: start: must be an object
start.flowstring必填已加载的 flow 名称读取文件时；未知的 flow 会被拒绝被拒绝：rule <n>: start.flow: unknown flow "<name>"
start.params任意 JSON 值缺省flow 的固定参数规则启动 flow 时不是纯 JSON 时被拒绝：rule <n>: ... is not JSON
objectstring必填固定的对象 id，或 $event.object规则启动 run 时被拒绝：rule <n>: object: must be a non-empty string
modestring必填observe、candidate、auto规则启动 run 时被拒绝：rule <n>: mode: must be "observe", "candidate", "auto"
schedulestring缺省使用本地时区的五字段 cron 表达式加载 cron 规则时；只有 source 为 cron 的规则使用它被拒绝：rule <n>: schedule: <why the cron expression is not valid>

cron 来源是来自 @operad-io/source-cron、名为 cron 的插件。对每条 source 为 cron 且带有 schedule 的规则，它在每个到期的分钟发出一个 tick；其他规则忽略 schedule。通过命令添加规则时，规则不能使用保留的来源 operad。

如果 triggers.json 无效，整个文件会被拒绝，信息中包含规则和字段。operad serve 会记录日志，并在文件修复之前不带来源运行；需要规则的命令会报告这一点。运行中的 serve 会监视该文件，并在新文件加载成功时重新加载。

从客户端修改设置#

operad settings 列出人可以调整的设置，operad settings set <name> <value> 修改其中一项；--repo <name> 指定一个已注册的仓库。全局设置是 <plugin>.<path>。文件名与其插件名相同的项目文件只使用插件名，所以 .operad/dev.json 对应 dev.concurrency、dev.autoDefault、dev.gate.commands、dev.gate.commandTimeoutSecs、dev.reviewer.use、dev.reviewer.args、dev.reviewer.timeoutSecs 和 dev.reviewer.fixLevel。其他文件会加上它的名称：.operad/review.json 对应 dev.review.default.levels、dev.review.default.rules 和 dev.review.default.fixLevel。更改会影响 merge 的内容（autoDefault、fixLevel、levels 和 rules）时需要 --yes。
