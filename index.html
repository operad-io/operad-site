A kernel with three words: flow, pending, history.

Everything else is a plugin.

Plan, work, verify, review, merge.

You ask

Describe a request with operad dev plan add, split it into tasks with operad dev task add, then confirm the plan.

An agent works

Each task gets its own git worktree and a brief. The worker commits there.

Checks run

The commands you list in .operad/dev.json run against the commit.

An agent reviews

A reviewer reads the change and writes a report. Findings send the task back for rework, up to a limit.

You merge

The task waits in pending. Merge lands it on main; reject sends it back with your note.

Any agent can work, and any agent can review.

claude, pi and radian are the workers the repository has plugins for. Each is a plugin you enable; pick them per repository, one for the worker and another for the reviewer.

// .operad/dev.json
{
  "workers":  { "claude": { "use": "claude/agent",
                            "args": ["--model", "sonnet"] } },
  "reviewer": { "use": "pi/agent",
                "args": ["--thinking", "medium"] }
}

The kernel is three words.

flow

The path a piece of work follows: steps, a wait for you, a wait for time, an end. operad flows lists the ones that are loaded.

pending

Everything that waits for you, in one list, with the actions each item offers.

words you learn. Every other word belongs to a plugin, so you never meet the ones you don't use.

  • dev plan, task, review, merge
  • chat a long conversation with an agent
  • bot a directory, an agent, skills
  • pool shared limits for each agent

Plugins are TypeScript files, loaded without a build step, small enough for an agent to write on the spot.

A plugin is type-checked before it runs.

Terminal, Claude Code, iPhone.

The terminal client.

operad tui finds operad serve or starts it, lists what is pending and running, and opens an object beside the list. a runs the main action, : opens the palette, q quits.

Claude Code, over MCP.

operad mcp is an MCP server on stdio. A lead agent reads pending, running and history, runs plugin commands, and takes the actions config.json allows. It never takes your decision: merge stays with you.

Its tools are list, show, section, pending, answer, running, history, command and act.

// .mcp.json
{ "mcpServers": {
    "operad": { "command": "operad",
                "args": ["mcp"] } } }

The iPhone app.

Run operad pair and scan the code. The app shows pending, running, each object's sections and its history, and asks before it merges. The server listens on this machine unless you give it a LAN or Tailscale address.

Run it on your own machine.

operad is in development. This is a first run on one of your repositories.

bun add -g @operad-io/cli

operad init
operad dev repo add .
operad dev plan add --slug hello --title "Add a greeting" < request.md
operad dev task add --plan P-0001-hello --slug greet --title "Print the greeting" < task.md
operad dev:confirm P-0001-hello
operad serve

operad pending
operad dev:merge T-0001-greet --yes

You need git, a repository with a remote, the Bun runtime (install it first; the operad command runs on it), and one of claude, pi or radian on your PATH. The commands and config.json keys are in docs/manual.md in the repository.

Not sure what goes in .operad/dev.json? Use the setup prompt.
